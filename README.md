# Display Harbor 0.1.5

macOS용 외장 모니터 창 정리 앱입니다. Rust 정적 라이브러리가 창 좌표 보정과 자동 실행 조건을 계산하고, SwiftUI + AppKit이 화면·메뉴 막대·권한·macOS API를 담당합니다.

[정식 릴리스 다운로드](https://github.com/alzkdpf/display-harbor/releases/tag/v0.1.5) · [테스트 요약](VALIDATION.md) · [보안 검토](SECURITY_REVIEW.md)

## 실행

배포 ZIP 안의 `Display Harbor.app`을 실행하세요. Apple Silicon, macOS 13 이상을 대상으로 빌드했습니다. 실제 화면 썸네일은 macOS 14 이상에서 지원합니다. 로컬 ad hoc 서명이며 Apple 공증은 받지 않았습니다.

1. 앱을 계속 둘 위치로 옮긴 뒤 실행합니다.
2. **손쉬운 사용 권한 설정**을 누르고 시스템 설정에서 Display Harbor를 허용합니다. 앱으로 돌아와 **권한 다시 확인**을 누릅니다.
3. 외장 모니터를 연결하고 **확장 전환 + 메인으로 모으기**로 창을 정리합니다.
4. **연결 시 자동 처리**를 켜면 현재 연결 상태에도 한 번 적용하며 이후 화면 구성이 바뀔 때 다시 실행합니다.
5. **창 새로고침**을 누르고 외장 화면을 선택합니다. 이동 가능한 창만 카드로 나타납니다. 카드를 클릭하면 선택한 외장 화면으로 이동하고, 같은 카드를 다시 클릭하면 메인 화면으로 돌아옵니다. 카드 이동은 미러링을 해제하지 않으므로 먼저 확장 모드로 전환해야 합니다.

카드 클릭 때마다 창의 실제 현재 위치를 다시 읽습니다. 사용자가 창을 직접 옮겼더라도 선택한 외장 화면 안에 있으면 메인으로, 그 외에는 선택한 외장 화면으로 이동합니다. 화면이 여러 개일 때는 현재 선택한 외장 화면과 메인 화면 사이를 전환합니다. 성공 후에도 카드 순서와 앱 패널을 유지해 연속해서 선택할 수 있습니다. 메인 복귀는 현재 크기를 메인 영역에 맞춰 배치하며 원래 좌표·크기를 복원하는 기능은 아닙니다.

외장 모니터가 없으면 카드와 아이콘은 볼 수 있지만 이동 버튼 역할의 카드는 비활성화되며 연결 안내가 표시됩니다.

자동 처리는 앱을 시작할 때 항상 꺼져 있습니다. 창을 닫아도 메뉴 막대에서 감시를 계속하며, 메뉴의 **종료**로 완전히 끝냅니다. 로그인 시 자동 실행 기능은 없습니다.

## 이미 권한을 켰는데 ‘권한 필요’일 때

이 빌드는 ad hoc 서명을 사용합니다. 이전 버전에 허용한 항목이 남아 있어도 현재 실행 파일에 권한이 적용되지 않을 수 있습니다. 이번 업데이트 후에도 한 번 다시 등록해야 할 수 있습니다.

1. **권한 다시 연결**을 누르면 현재 실행 중인 앱 경로와 재등록 절차를 보여 줍니다.
2. 안내 버튼으로 시스템 설정과 Finder를 엽니다. 손쉬운 사용 목록의 기존 Display Harbor 항목을 **−로 제거**합니다.
3. **+**로 Finder에서 표시한 현재 앱을 추가하고 허용합니다. 같은 이름의 다른 사본을 선택하지 않도록 확인하세요.
4. 앱으로 돌아와 **권한 다시 확인**을 누릅니다. 여전히 권한 필요라면 **앱 다시 시작**을 누릅니다.

앱이 권한을 자동 변경하거나 허용 상태를 우회하지는 않습니다. **현재 실행 중인 앱 위치**에서 등록해야 할 앱 경로를 복사할 수 있습니다. 다른 앱의 권한을 초기화하지 않습니다.

권한은 1초마다, 그리고 앱으로 돌아올 때 다시 확인합니다. 권한이 없을 때는 자동 실행 기회를 소모하지 않으며 허용된 뒤 현재 화면 구성에서 다시 시도합니다. 수동 정리는 외장 모니터 없이도 테스트할 수 있습니다. 외장 화면으로 보내기는 실제 확장 화면이 필요합니다.

## 표시할 창과 제외할 항목

macOS의 `/System/Library/CoreServices/WindowManager.app`이 소유한 화면 관리용 표면은 사용자 창 목록에서 제외합니다. 앱 이름이 WindowManager인 제삼자 앱이나 Finder는 이 필터로 제외하지 않습니다. 제외된 관리용 표면 수는 진단에 따로 기록합니다.

카드는 일반 앱의 실제 창 중 유효한 접근성 제어 핸들, 정상 크기·좌표, 위치 변경 권한을 모두 확인한 창만 표시합니다. 창이 없는 앱, 메뉴 막대용 보조 프로세스, 접근성 제어 정보가 없는 항목, 최소화·전체 화면·이동 미지원 창은 카드에서 제외합니다. 지원되지 않는 항목의 이름이나 비활성 행은 기본 화면에 표시하지 않습니다.

화면 시스템과 접근성 목록을 결합할 때 실제 대상의 프로세스·위치·크기가 유일하게 일치해야 합니다. 구분할 수 없는 후보는 제외합니다. 클릭 직전 다시 이동 가능 여부를 검증하고, 이미 닫혔거나 이동 불가로 바뀐 창은 카드에서 제거합니다. 이동 처리는 백그라운드에서 직렬로 실행하며 완료 후 다음 카드를 클릭할 수 있습니다.

**창 조회 진단**에만 권한 상태, 창 수, 제외 개수, 접근성 역할, 조회 오류 코드의 개수를 기록합니다. **진단 복사**에는 창 제목이나 개인 문서 내용이 포함되지 않습니다.

권한은 허용인데 유효 창이 0개이고 `AXApplication` 역할만 반환된다면 이동할 수 있는 카드도 표시할 수 없습니다. 권한 부족과 같은 문제로 취급하지 않고 안내를 표시합니다. 이전 검증에서 이 현상이 있었으나 현재 검증에서는 유효한 창이 다시 인식됐습니다. 환경에 따라 모든 앱의 창 제어를 보장하지는 않습니다.

별도 프로젝트에도 [유사한 접근성 현상](https://github.com/Hammerspoon/hammerspoon/issues/3914)이 보고돼 있습니다. 두 현상의 원인이 같거나 macOS 자체 결함으로 확정됐다는 의미는 아닙니다.

## 카드 미리보기

기본은 앱 아이콘과 창 제목입니다. **실제 창 미리보기**를 명시적으로 켰을 때만 화면 기록 권한을 요청하고 ScreenCaptureKit으로 창별 정지 이미지를 가져옵니다. 권한을 주지 않아도 카드 이동은 사용할 수 있습니다. 캡처가 실패하거나 대상을 유일하게 구분하지 못하면 앱 아이콘을 유지합니다.

미리보기는 켤 때와 목록 새로고침 후에 갱신하는 스냅샷이며 연속 영상이 아닙니다. 한 번에 최대 48개를 캡처하고 나머지는 아이콘으로 표시합니다. 오디오는 캡처하지 않으며, 이미지는 메모리에만 보관하고 파일로 저장하거나 전송하지 않습니다. 앱을 다시 시작하면 미리보기는 꺼진 상태입니다.

## 동작

- 1초 간격으로 연결된 화면 ID, 미러링 상태, 좌표를 확인하고 2회 안정된 상태를 기다립니다. 연결·해제, 미러링 변경, 화면 배치나 해상도 변경이 자동 정리를 다시 유발할 수 있습니다.
- 미러링된 화면은 Core Graphics로 세션 동안 확장 모드로 전환하고 메인 화면 오른쪽에 배치합니다. 이미 확장된 모니터의 배치는 유지합니다.
- 전환 뒤 2초 기다린 후 일반 앱의 접근 가능한 창을 시스템의 메인 디스플레이로 모읍니다. 창 크기가 너무 크면 사용 가능한 영역에 맞춰 줄이고 Dock·메뉴 막대를 피합니다.
- 자동 처리는 한 번 실행한 뒤 대기합니다. 사용자가 나중에 확장 화면으로 옮긴 창을 반복해서 끌어오지 않습니다. 새 창을 계속 감시하거나 특정 창만 남도록 강제하는 기능은 없습니다.
- 성공·건너뜀·실패 수를 표시합니다. 실제 실행 중의 실패는 자동 반복하지 않으며 수동 버튼으로 다시 실행할 수 있습니다.
- 메인은 macOS가 지정한 메인 화면입니다. 내장 화면으로 강제 변경하지 않습니다. 외장 모니터가 여러 개면 보내기 대상 화면을 선택할 수 있습니다.

## 제한과 검증

전체 화면·최소화 창은 건너뜁니다. 다른 Space, Stage Manager, 자체 창 관리 기능, AX API 미지원 앱의 창은 이동을 보장할 수 없습니다. Display Harbor 자체 창은 정리 대상에서 제외합니다. 창 위치·크기를 복원하는 기능은 없습니다. 종료해도 이미 이동한 창이나 세션의 확장 설정은 되돌리지 않습니다.

검증 결과와 실제 모니터 테스트의 제한은 [VALIDATION.md](VALIDATION.md)를 보세요.

이 앱은 네트워크 요청을 하지 않고 창 목록과 최근 기록은 실행 중 메모리에만 보관합니다.

## 다시 빌드

Rust stable과 Xcode Command Line Tools가 필요합니다. `rtk`는 선택 사항이며 설치되지 않았으면 빌드 스크립트가 명령을 그대로 실행합니다.

```sh
bash build.sh
```

핵심 소스: `core/src/lib.rs`, `native/App.swift`, `native/WindowDiscovery.swift`, `native/WindowMover.swift`, `native/WindowPreviews.swift`. 테스트와 빌드 명령은 `build.sh`에서 관리합니다. Rust 외부 crate 의존성은 없습니다. 기본 빌드 결과는 `dist/Display Harbor.app`이며 `DISPLAY_HARBOR_APP_OUTPUT`으로 다른 출력 경로를 지정할 수 있습니다.

앱 실행 중에는 빌드가 기존 실행 파일을 덮어쓰지 않도록 중단합니다. 아이콘은 `native/MakeIcon.swift`에서 생성하며 Finder·Dock·권한 화면에 쓰는 ICNS로 패키징합니다. 정상 서명 인증서가 있는 경우 `DISPLAY_HARBOR_SIGNING_IDENTITY` 환경 변수에 해당 서명 identity를 지정할 수 있습니다. 이 환경에는 사용 가능한 서명 인증서가 없어 ad hoc으로 빌드했습니다. 인증서가 없는 상태에서 업데이트마다 권한 유지까지 보장하지는 않습니다.
